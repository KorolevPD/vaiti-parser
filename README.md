# Vaiti Parser
Сервис `vaiti-parser` разработан для карьерного сервиса [«Вайти»](https://vaiti.tech/) и отвечает за "грязный" парсинг DOM-структуры сайтов и обход блокировок (ротация прокси). Он собирает данные с площадок, не предоставляющих публичного или удобного API, таких как Avito, Habr Career, Dreamjob и другие. Сервис парсит вакансии, зарплатные вилки и рейтинги компаний, после чего отправляет собранную информацию в Kafka.

## Архитектура
* **Парсеры (`app/parsers/`)**: Содержат логику извлечения данных с конкретных площадок. Каждый парсер использует свои стратегии и селекторы.
* **Прокси (`app/proxy/`)**: Модуль управления пулом прокси-серверов. Отвечает за ротацию и управление cooldown'ами для минимизации риска блокировки (капчи/403).

## Технологический стек
* Python 3.11+ (менеджер пакетов Poetry)
* SQLAlchemy 2 & SQLModel, Alembic (PostgreSQL / SQLite)
* BeautifulSoup4 (парсинг HTML)
* Confluent Kafka
* APScheduler (планирование задач парсинга)

## Kafka Топики (Outbound)
Сервис публикует собранные сущности в следующие топики Kafka:
* `vacancy.discovered` - Обнаруженные новые вакансии
* `vacancy.archived` - Архивные вакансии
* `rating.discovered` - Собранные рейтинги компаний
* `salary.discovered` - Собранные зарплатные ожидания/вилки

## Бизнес-логика и Pipeline сбора

Сбор данных в `vaiti-parser` спроектирован для надежного "умного" парсинга и обхода блокировок:

### 1. Расписание (Timing)
Планирование задач управляется библиотекой `APScheduler` с использованием `SQLAlchemyJobStore` для сохранения состояния (чтобы задачи не терялись при перезапуске):
* **Ежедневно (Daily, 02:00):** Парсинг вакансий с Avito (`AvitoVacanciesParser`) и Хабр Карьеры (`HabrVacancyParser`).
* **Еженедельно (Weekly, Пн 02:00):** Парсинг рейтингов компаний с Dreamjob (`DreamjobRatingParser`) и Хабра (`HarbRatingParser`).
* **Ежемесячно (Monthly, 1-е число 02:00):** Парсинг зарплатных вилок и статистики (`HabrSalaryParser`).

### 2. End-to-End Pipeline
1. **Trigger:** `AsyncIOScheduler` вызывает функцию `run_parser`, инициируя класс конкретного парсера.
2. **Proxy Rotation & Rate Limiting:** Запросы проходят через `SharedHttpClient` с настроенным `ProxyController`, который отслеживает ошибки (например, 403 Forbidden или капчу) и автоматически производит ротацию прокси при необходимости (вызывая `ProxyRefreshRequired`). Между запросами соблюдаются случайные задержки (delay range).
3. **Discovery Phase:** Парсер итерируется по страницам каталога или API (например, `run_search` в Avito), извлекая базовую метаинформацию (ID, заголовок, ссылку), и первично сохраняет сущности в локальную БД.
4. **Completion Phase:** Парсер обходит сохраненные "неполные" сущности (`complete_missing_details`), заходит на страницу каждой конкретной вакансии, чтобы собрать полное описание и недостающие детали.
5. **Publishing:** Полностью собранная вакансия (или рейтинг/зарплата) отправляется в Kafka-топик (`vacancy.discovered`, `rating.discovered` или `salary.discovered`) через `KafkaProducer.send()`. Если при сборе выясняется, что страница удалена, вакансия отправляется в `vacancy.archived`.

### 3. Фильтрация и Дедупликация
* **Дедупликация (Storage-level):** При вызове функции `save(objs)` в модуле `storage.py`, ORM (SQLModel/SQLAlchemy) проверяет наличие записи по первичному ключу. Если запись существует, она обновляется (Update), если нет — создается новая (Insert). Таким образом, дубликатов в БД не возникает.
* **Фильтрация (Parser-level):** Логика фильтрации заложена в конфигурацию самих парсеров (например, списки `include`, `exclude` и `global_exclude` в `config.yaml` для Avito). При парсинге отбрасываются элементы, содержащие стоп-слова или не соответствующие IT-тематике, до того как они попадут в базу.

## Локальный запуск и развертывание

### Запуск через Docker (Рекомендуемый для Production-like окружения)

Сервис полностью докеризирован. При запуске контейнера автоматически применяются миграции БД (`alembic upgrade head`), после чего стартует основное приложение (`python main.py`).

1. Соберите Docker-образ из директории `vaiti-parser`:
```bash
docker build -t vaiti-parser .
```

2. Запустите контейнер, передав файл с переменными окружения:
```bash
docker run --env-file .env -d vaiti-parser
```

### Запуск "Raw" (Для разработки)

Для локального запуска вне контейнера:

1. Установите зависимости:
```bash
poetry install
```

2. Примените миграции базы данных:
```bash
poetry run alembic upgrade head
```

3. Запустите сервис:
```bash
poetry run python main.py
```
